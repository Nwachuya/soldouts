## Objective
Keep the LLM run intentional while making the newest available queue and analysis usable across devices and during a rep's loss of connectivity:
1. **Shared Persistent Store**: Use a site-wide Netlify Blobs store, with strong-consistency reads, as the server-side source of truth. Save the latest sold-out snapshot by team date and save each merchant's fetched history, verified signal, quote, `source_hash`, and processing timestamp under separate merchant keys. All server instances and rep devices must read the same records across function restarts and new deploys. Local runtime JSON and browser storage must not be treated as shared persistence. Do not use a deploy-specific store or silently report a failed shared write as a successful sync.
2. **Text-Hash Change Detection ("Pending AI Processing")**: Compute a deterministic SHA-256 `text_hash` over each merchant's live notes, Deal Alert replies, reviews, and refunds. Merchants whose `text_hash` differs from their cached `source_hash` (or have never been processed) are flagged `pending_ai: true` in the UI and counted in the Sync/AI drawer. Unchanged merchants are never reprocessed.
3. **Complete, Intentional "Run LLM" Action**: The existing button calls `POST /api/llm/refresh`; that action must fetch the latest sandbox text before deciding what is pending. Follow the sandbox's `next_cursor` pagination for rep notes, Deal Alert replies, reviews, and refund reasons. Clean/deduplicate the full fetched set and evaluate all four source types; remove silent `limit=5` and first-ten-record omissions. If the LLM needs a bounded prompt, select relevant evidence from every source explicitly and retain the full-source hash. Run `claude-haiku-5-5` with thinking disabled and the per-run spend cap only for pending merchants; apply substring quote verification and actionable-signal downgrade guards. Write accepted verdicts and reviewed source hashes to the shared store before reporting success, then refresh recommendations. Failed or budget-deferred merchants remain pending with a visible count. No automatic LLM run is required or wanted.
4. **Online Snapshot to Device**: Whenever an online open/refresh obtains today's live queue and shared analysis, save the complete displayed queue, merchant details needed in the field, marks, verdicts/quotes, and timestamps in IndexedDB on that device. Replace the one-payload `localStorage` fallback as the primary offline store. Keep the newest successfully synced snapshot; label its date and time so yesterday's data is never presented as today's.
5. **Usable Without Device Connectivity**: Cache the app shell and required assets with a service worker so a rep who previously opened the app can reload it without internet. Read the latest IndexedDB snapshot when network requests fail; browsing the queue and merchant history and seeing the saved action, £ value, quote, and sync timestamp must still work. If the device has never received a snapshot, show an explicit no-offline-data state instead of presenting the old bundled CSV sold-outs as today's work.
6. **Offline Rep Changes and Automatic Upload**: Saving or clearing a merchant mark while offline must update the local view and persist an operation with a stable ID in an IndexedDB outbox. On reconnect, automatically retry the outbox through the app server to the sandbox mark endpoint and update the shared mark view; remove an operation only after server acknowledgement. Show pending/synced/error state. Replays must be idempotent, and a newer mark from another rep must produce a visible conflict instead of being silently overwritten. Do not run the LLM automatically on reconnect.
7. **Rep Controls**: Keep the footer's pending count, Run LLM button, live/offline state, latest snapshot timestamp, LLM timestamp, and offline-change sync status. Opening or refreshing the app may fetch today's queue, but only the button runs the LLM. Online merchant marks continue to use the sandbox mark endpoints.

## Evaluation Criteria
1. **Zero Redundant LLM Calls**: Merchants whose `text_hash` matches cached `source_hash` are skipped (`skipped_unchanged` count returned; `$0.00` spent when 0 pending).
2. **Quote & Downgrade Safety**: All LLM outputs pass substring quote verification and `should_accept_llm_override` parity rules before saving.
3. **Cross-Device Persistence**: After rep A runs the LLM, rep B on a different device sees the same verdict, quote, source hash, and pending count after refresh, without rep A's browser storage. The result survives a function restart and a new deploy; concurrent merchant updates do not overwrite unrelated merchants.
4. **Fresh Offline Fallback**: If the sandbox fails but the app is reachable, serve the latest shared sold-out snapshot and analysis. If the device itself loses connectivity, the installed app reads its latest IndexedDB snapshot, including verdicts, quotes, marks, recommendations, and an unambiguous `last_synced_at`/snapshot date. The old bundled sold-outs must never masquerade as current work.
5. **Source Completeness**: Pagination and processing tests cover more than five records per source and enough notes/replies to push reviews/refunds past the first ten records. An unchanged full-source hash causes no LLM call; a changed record in any of the four sources becomes pending. Budget or request failures leave the merchant pending.
6. **Offline Mark Replay**: With the device disconnected, a saved and a cleared mark survive reload and visibly remain pending. After reconnect, each uploads automatically once, becomes visible on a second device, and leaves the outbox only after acknowledgement; simulated failed uploads retry, while conflicting changes are shown for resolution.
7. **UI & Global Rules**: Footer button follows `15px 20px` `.coss-btn` padding, `99vw` shell width, zero overflow, and clean `@base-ui/react` Dialog accessibility. Offline, stale-snapshot, and pending-upload labels remain clear on a phone.
8. **Tests & Build**: Storage, pagination, offline-shell, IndexedDB, outbox replay/conflict tests, `cd web && npm test && npm run build`, a disconnected-device reload, and a two-device local/preview check pass before this task returns to `done`.
